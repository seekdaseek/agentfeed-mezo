Problem

Agents are customers that banks and APIs can't serve.

  • An agent can't open an account, pass KYC or keep a monthly subscription.
  • It holds a wallet, not an API key, and often no gas token on the chain it pays on.
  • Stablecoin payments for agents exist, but most are built for USDC and EIP-3009. MUSD, Bitcoin-backed and on Mezo, has none of that plumbing.
  • So the Bitcoin economy's own dollar is not yet something an agent can spend.
Track 2: how might we make MUSD easier to discover, access and use?

Why MUSD

Built to fit the token as deployed.

EIP-3009 transferWithAuthorizationabsent, so x402 "exact" is not possible

  • Permit gives the same one-signature UX on MUSD: agent needs no gas.
  • Depth: signature checked against MUSD's live domain and nonce, permit() simulated before spending gas, MUSD minted via Mezo Borrow.

Wave 2 · Nov 2 to 15

From a rail to a distribution surface.

  • Mezo mainnet MUSD: same code, mainnet config, a per-call gas surcharge.
  • MUSD on Base: agents that live on Base pay without bridging.
  • Telegram bot: a person tops up a MUSD budget, sets caps, the bot signs permits for their agents. Agents never hold a key.
  • Spend allowance: one permit, many calls, so agents can call in parallel.

Why we keep going: AgentFeed already has paying agents. MUSD is one more way for them to pay.
